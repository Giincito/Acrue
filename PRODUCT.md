# Product

## Register

product

## Users

Acrue is built for a single Spanish-speaking user managing academic work, personal finances, home routines, habits, recipes, wishlist items, and study focus from one installable PWA. The user context is daily, practical, and often time-sensitive: capturing tasks quickly, reviewing calendars, studying, logging expenses, checking pantry data, and asking AI for help without switching tools.

## Product Purpose

Acrue is a personal LifeOS that makes accumulated progress visible. It centralizes life operations across study, tasks, calendar, finances, pantry, recipes, habits, wishlist, and a "Cerebro" module for focus, review, and semantic notes. Success means the user can capture or retrieve useful information with minimal friction, recover from mistakes, keep working offline when needed, and trust external integrations to fail gracefully instead of blocking core workflows.

## Brand Personality

Quiet, precise, and compounding. Acrue should feel calm and capable rather than decorative: a disciplined personal operating system where small actions add up. The voice is direct, human, and Spanish-first, with interface copy that explains the next action without over-teaching.

## Anti-references

Avoid marketing-style dashboards, oversized hero layouts inside the app, decorative card grids, colorful productivity gamification, noisy gradients, generic AI SaaS visuals, and UI that looks disconnected from the existing monochrome Acrue system. Avoid dry placeholder behavior that only says "listo" without giving the user an actionable workflow. Avoid exposing implementation details, IDs, or raw integration failures when a human label or recoverable message is available.

## Design Principles

- Capture in seconds: common actions should be reachable quickly and not require configuration before value.
- Calm density: show enough information for repeated daily use without making operational screens feel like landing pages.
- AI as a collaborator: AI should route intent, summarize, suggest, and recover, but user-visible controls stay explicit and reversible.
- Resilience first: external APIs, sync, and AI failures must degrade gracefully and keep local workflows usable.
- Progress compounds: completed actions, study sessions, habits, and records should make accumulated progress legible without turning the app into a game.

## Accessibility & Inclusion

Target WCAG 2.1 AA. Preserve keyboard access, visible focus states, semantic controls, 44px minimum touch targets, reduced-motion respect, and non-color-only status cues. The product is Spanish-first, so labels, errors, and empty states should use natural Spanish and avoid untranslated internal terms.
